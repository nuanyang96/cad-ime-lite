# 变更说明 v7（2026-11-07）

## 这一版解决什么

**把"发给别人"从 6 个文件降到 2 个（一个 exe + 一份说明）。**

以前给别人用，要凑齐 6 个文件并手动做 3 件事：

| 以前必须做 | 现在 |
|---|---|
| 给 `CadImeLite.exe` | ✅ 还是给 exe |
| 给 `rules.ini` | ✅ 已内嵌，缺了自动写 |
| 给 `安装-CadImeLite.bat` | ✅ exe 自己复制自己、自己加自启 |
| 给 `CadImeSwitch.lsp` | ✅ 已内嵌，自动写到 `C:\CadImeSwitch\` |
| 给 `autoload.lsp` | ✅ 已内嵌，自动写 |
| 教对方去 `APPLOAD` 加启动组 | ✅ 自动登记注册表启动组 |

对方流程：**双击 exe → 重启一次 CAD → 完事**。

## 实现方式

### 内嵌资源

exe 里打进 3 个文件（编译时 `/resource:`）：

| 资源 | 大小 | 用途 |
|---|---|---|
| `CadImeSwitch.lsp` | 10,853 | AutoLISP 主体（自带 `(c:imesw-on)`） |
| `autoload.lsp` | 749 | 入口：加载主体并启动反应器 |
| `rules.ini` | 2,070 | 默认配置（窗口类名表等） |

exe 从 44,032 → 60,928 字节，就是这个代价。

### 启动时自装（`SelfInstall()`）

每次启动按顺序自检，**每步都包 try/catch，失败不阻断启动**，只写日志：

| 步 | 动作 | 判断依据 |
|---|---|---|
| ① | 写两个 LSP 到 `C:\CadImeSwitch\` | 内容不同才写（升级能覆盖，平时不动文件时间） |
| ② | 登记 AutoCAD 启动组 | 已存在则跳过；不存在则追加，并修 `NumStartup` |
| ③ | 复制自身到 `%LOCALAPPDATA%\CadImeLite\` 并重启 | 只在"不是从该目录运行"时做 |
| ④ | 写默认 `rules.ini` | **仅当不存在**，绝不覆盖用户改过的 |
| ⑤ | 加 `HKCU\...\Run\CadImeLite` 自启 | 每次覆盖为正确路径 |

**③ 的关键细节**：复制后要 `Process.Start` 新实例，但**必须先释放互斥体**，
否则新实例拿不到 `Global\CadImeLite.SingleInstance` 会直接退出 ——
表现就是"双击没反应"。所以 Main 里是：

```csharp
if (!SelfInstall())
{
    // 先释放，再启动，再退出，顺序不能反
    _singleMutex.ReleaseMutex();
    Process.Start(_pendingRelaunch);
    return;
}
```

### 启动组登记的正确性

AutoCAD 启动组的真实位置（实测确认）：

```
HKCU\Software\Autodesk\AutoCAD\R24.3\ACAD-7101:804\Profiles\<配置名>\Dialogs\Appload\Startup
    NumStartup = 4          (DWORD)
    1Startup   = ...
    4Startup   = ...
```

注意 **配置名随机器不同**（本机是 `<<未命名配置>>`），所以代码是**遍历所有版本、
所有配置**，不是写死路径。

### 为什么登记 `autoload.lsp` 而不是 `CadImeSwitch.lsp`

这是**故意**的。本机（以及任何从 v6.5 升级的机器）启动组里已经登记了
`autoload.lsp`，`acaddoc.lsp` 也可能加载它。如果改登记 `CadImeSwitch.lsp`，
就会**两处都加载 → 命令反应器重复注册**，行为不可预期。

所以照原样：两个 LSP 都写出去，只登记 `autoload.lsp` 这一个入口。

### 登记失败自动重试

场景：对方先装程序、后开 CAD —— 装机时注册表里还没有 AutoCAD 配置项，
登记不了。用户之后打开一次 CAD，程序在 `Tick()` 里**每 10 秒重试一次，最多 60 次**，
自己补上，不需要再双击程序。

## 已知限制（沿用 v6.5）

1. 微信输入法 / 搜狗拼音下，命令行按 `Shift` 无反应（`open` 通道是"关输入法"而非改模式）
2. `open` 通道偶发设不上，程序会重试/降级，最终结果正确
3. 依赖 LSP 提供多行文字判据；LSP 没加载时多行文字会被判成英文
4. 第三方输入法靠模块名匹配，名单外的走"未识别"回落
5. 本机禁止 NETLOAD 外部 .NET 程序集，所以只能走 AutoLISP 通道
