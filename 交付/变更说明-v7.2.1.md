# 变更说明 v7.2.1（2026-11-19）

## 改了什么

**只改日志显示，功能与 v7.2 完全一致。**

v7.2 把判断依据从「全局那一条状态」换成了「每个 CAD 各一份记忆」，但写日志时用的还是全局那条
（`_lspLine`），于是两个 CAD 互切时会打出这种看着自相矛盾的行：

```
判据=LSP(IDLE) 目标=中
```

含义其实是「全局最后一条是 IDLE（另一个 CAD 写的），但当前这个 CAD 的记忆是中文」。
功能是对的，日志是错的——排查时会被这行绕进去。

现在日志显示**真正驱动这次判断的那条**：同样的场景会打成

```
判据=LSP(CN) 目标=中
```

## 验证

复用同一套反射单测，跑「A 编辑文字 → 切 B → B 敲命令 → 回 A」：

| 版本 | 回 A 的判断 | 日志显示的状态 |
|---|---|---|
| v7.2 | 中（正确） | **EN（错位）** |
| v7.2.1 | 中（正确） | **CN（正确）** |

行为序列三版一致（`切B=False`、`B命令=want0`、`回A=want1`），只有显示变量变了；
注册表快照后原值还回，没碰运行中的 CAD。

编译参数不变：`csc /target:winexe /platform:x64 /optimize+`，内嵌 3 个资源，
61,440 字节，SHA256 `E7093BBB…931C`，二进制内确认有 `启动 v7.2.1 scope=`。

## 影响面

- 不改 LSP，**不用重启 CAD**
- 不改判断逻辑，不需要重新验收两个 CAD 的场景（想验也就那三步）
- 唯一可见变化：日志里那行括号内的状态值
