# CadImeLite v4 变更（2026-10-24 10:51）

## 问题

CAD 2024 的命令行是 **WPF 窗口**，类名 `HwndWrapper[DefaultDomain;;<GUID>`，GUID 每次启动都变（韩工机器上是 `7af9152d-f8ed-40e2-9332-d8acf85f799f`）。
`rules.ini` 用精确类名匹配，永远命中不了它，所以敲 `abc` 出的是拼音候选。

## 改了什么

1. **匹配器支持前缀**：`rules.ini` 里写 `键*=值`，按键名前缀匹配。
   焦点控件**或它的父链**上任意一级命中即算（WPF 的焦点可能落在子窗口上）。
2. 判定优先级变成三段：
   `绘图区(MDIClient)` → 中文  >  `前缀规则`  >  `精确类名表` → 无匹配则不动。
3. 日志 `判据=` 现在会写出是哪个前缀命中的：`判据=前缀(HwndWrapper[DefaultDomain)`。
4. 新增 `rules.ini` 行：`HwndWrapper[DefaultDomain*=0`（内置兜底同值，ini 里没写也会生效）。

## 验证（本机自测，10:51）

`selftest5`：host4.exe 造一个真 WPF 风格窗口（类名带 GUID，等价于 CAD 命令行），先压成中文再 Tick：

```
cls=HwndWrapper[DefaultDomain;;7af9152d-test]
准备态 conv=0x0001（中文）
Tick 后 conv=0x0000 native=False（英文）
日志: 判据=前缀(HwndWrapper[DefaultDomain) 目标=英 conv 0x0401->0x0000 OK
结论: 前缀判据=通过 / 切成英文=通过
```

回归（前两版的能力没被破坏）：

```
selftest3: A 绘图区 conv 0x0000->0x0401 判据=绘图区(MDIClient)  / B 命令行 conv 0x0401->0x0000 判据=类名表   通过
selftest4: 离开acad 复位=中文 窗口=0xF149A conv 0x0000->0x0401 OK / 只复位一次   通过
```

## 已知副作用（写出来，别等它咬人）

- CAD 进程里所有 WPF 窗口（特性面板、部分对话框）都会判成英文。要在那里输入中文，按一下 Shift 就行；工具只在焦点变化时动一次，不会把你按的 Shift 改回去。
- 如果命令行窗口的**焦点子窗口**类名不在这条前缀下、父链也不到 7 层，可能仍不命中。日志里 cls + 父链能立刻看出来。

## 验收

1. `更新-CadImeLite.bat`（先停进程 → 覆盖 exe 和 rules.ini → 重启）
2. 命令行敲 `abc` → 出英文字母，日志 `判据=前缀(HwndWrapper[DefaultDomain)`
3. 双击多行文字 → 直接中文，日志 `判据=绘图区(MDIClient)`
4. 切到微信 → 直接中文，日志 `离开acad 复位=中文`
