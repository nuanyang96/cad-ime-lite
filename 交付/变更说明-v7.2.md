# 变更说明 v7.2（2026-11-19）

## 这一版解决什么

**两个 CAD 同开时，一个 CAD 里没退出的文字编辑会被另一个 CAD 的状态冲掉，回到原 CAD 打不出中文。**

场景（v7.1 实测复现）：

1. CAD A（2024）双击多行文字，光标停在编辑框里 → LSP 写 `Line3=CN`
2. 切到 CAD B（2018），敲一条命令 → B 的 LSP 写 `Line3=EN`/`IDLE`
3. 切回 A 的编辑框 → 全局状态现在是 B 写的英文，A 也判成英文 → **打不出中文**

v7.1 已经堵住了反方向（A 的中文盖到 B 的绘图区、命令被吃），这一版把剩下这半边也补上。

## 做法

不再用"全局那一条状态"下判断，改成**每个 CAD 进程各记一份**。

`TryLspWant()` 里加了两张表：

```csharp
static readonly Dictionary<uint, int>      _wantByPid;   // pid -> 目标中(1)/英(0)
static readonly Dictionary<uint, DateTime> _atByPid;     // pid -> 何时记的
```

- 每看到一次注册表状态**变化**，就按"当时前台的那个 CAD 进程"记一份
- 判断时只查**当前 pid 自己那份**；查不到（这个 CAD 还没写过状态）就退回窗口判据——绘图区判英文，命令一定敲得进去
- 单份记忆 120 分钟没更新就丢弃，防止反应器死掉后状态永久卡住

另外把 `Hits` 加进了变化判据（`cmd|line|hits`）：两个 CAD 先后执行同名命令时，`cmd+line` 可能一模一样，只看这两项会以为"没变化"。两个实例的计数器各自独立，带上它更容易认出是另一次写入。

**不需要改 LSP，也不需要重启 CAD**——LSP 写在 `C:\CadImeSwitch` 的内容没动，托盘换掉即可。

## 验证

沿用 v7.1 那套办法：编成库，反射调私有方法 `TryLspWant()`，注册表快照 + 还原（测完原值一字不差还回去），用两个假 pid 模拟两个 CAD。

同一套步骤跑三个版本：

| 步骤 | v7 | v7.1 | v7.2 |
|---|---|---|---|
| 首次读到（只记账） | 英 | 英 | 英 |
| A 进多行文字 | 中 | 中 | 中 |
| **切到 B** | **中（串台）** | 英 | 英 |
| B 敲命令 | 英 | 英 | 英 |
| **回到 A 的编辑框** | **英（丢了）** | **英（丢了）** | **中 ✅** |
| A 退出编辑 | 英 | 英 | 英 |

编译：`csc /target:winexe /platform:x64 /optimize+`，内嵌 3 个资源，61,440 字节，
资源名与 PE 架构核对通过，二进制里确认含 `启动 v7.2` 与新日志串。

## 仍然存在的限制

1. **两个 CAD 几乎同时进入同一个文字命令**时，后一个可能仍不切中文——记忆是按 pid 记的，但"同一份写入内容"在极端时序下仍可能认成同一次。要根治得给 LSP 加每实例随机 token，那要重启 CAD，暂不做。
2. 打 `MTEXT`/`TEXT` 命令名中途被切成中文、需要再按回车——反应器的固有行为，历史试过 DELAY 会破坏 SAVE，不动。
3. 单份记忆超过 120 分钟没更新会失效（比如在一个编辑框里连续待两小时），退出重进即可。

## 回退

`交付\v7.1\CadImeLite.exe` 是 v7.1 原件，双击即可回退；也提供了 `交付\回滚到v7.1.cmd`。

## 升级注意

托盘运行时自身 exe 被锁，**不能直接覆盖**（`File.Copy` 失败后会因单实例锁静默退出，表现是"双击没反应"）。

`交付\更新到v7.2.cmd` 会直接替换；如果提示 copy failed，先从托盘右键「退出」再跑一次。
**不需要重启 CAD。**
