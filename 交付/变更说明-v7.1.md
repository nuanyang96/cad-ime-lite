# 变更说明 v7.1（2026-11-19）

## 这一版解决什么

**两个 CAD 同时打开时，输入法状态会串台：一个 CAD 里的「中文」会盖到另一个 CAD 上，导致命令被输入法吃掉。**

韩工反馈的原话是「该英文时是中文，只有两个 CAD 都开时才犯」。本机当时 2024（`2000-鲁西园区现状图…dwg`）和 2018（`总平面布置图（10.26）.dwg`，只读）确实同时开着，条件成立。

## 根因

两个 CAD 实例共用一个注册表状态键：

```
HKCU\Software\CadImeSwitch\Line3  =  CN / EN / IDLE
```

`CadImeSwitch.lsp` 在**任一** CAD 里执行命令都会改写它。而 v7 为了让「切到另一个 CAD 也不失效」，**主动去掉了「写入者必须就是当前前台进程」这条校验**（`Lite.cs` 里 v7 的注释写着「代价是极端情况下会短暂沿用另一个 CAD 的状态，下一条命令即自愈」）。

实测这个「短暂」并不短暂：

| 时刻 | 发生了什么 |
|---|---|
| CAD A 双击多行文字 | A 的 LSP 写 `Line3=CN` |
| 切到 CAD B 的绘图区 | Lite 读到 `CN`，**照样把 B 设成中文** |
| 在 B 里敲 `L`、`CO` | 字母被中文输入法吃掉，命令不出来 |
| 只要两个 CAD 都不执行新命令 | 这个中文状态**一直保持**，不会自愈 |

## 改了什么

`src/v2/Lite.cs` 的 `TryLspWant()`：恢复进程绑定。

```csharp
if (_lspPid != pid)
{
    // 记一次日志（同 pid 组合不重复写），然后不采用这条状态
    return false;
}
```

`pid` 不符时返回 false，**退回原来的窗口判据**——绘图区判英文，所以命令一定能敲进去。等该 CAD 自己执行命令、写入新状态时，绑定会自动更新，不需要人工干预。

## 验证

### 单元级（不碰 CAD）

把同一份 `Lite.cs` 分别按 v7（改前）和 v7.1（改后）编译成库，直接调私有方法 `TryLspWant()`，模拟两个进程 id：

| 步骤 | v7 | v7.1 |
|---|---|---|
| 首次读到状态（只记账） | False | False |
| 状态变化、同一 pid | True / 目标=英 | True / 目标=英 |
| **换成另一个 pid** | **True / 目标=英（照收）** | **False（不采用）** |
| 另一个 pid 写入 `CN` | True / 目标=中 | True / 目标=中 |
| **回到原 pid 读 `CN`** | **True / 目标=中（串台）** | **False（退回窗口判据）** |

最后一行就是韩工遇到的现场。

### 待现场验收

需要两个 CAD 同开实测，步骤见 `使用说明.md` 的「装完怎么验证」扩展项，或直接按下面做：

1. CAD A 双击多行文字，光标停在编辑框里
2. 切到 CAD B 的绘图区，敲 `L` → **应直接出命令提示**（v7 会卡住）
3. 切回 A 的编辑框 → 仍能打中文
4. 在 B 里双击一个多行文字 → 仍能打中文

## 已知代价（没根治的部分）

A 里**没退出**的多行文字，如果期间 B 执行过命令，回到 A 会按 B 写的 `IDLE` 判成英文——这是「两个 CAD 共用一个全局键」的固有限制，v7 也有，v7.1 没有变差。

要根治得按进程分键（LSP 侧要能拿到自己的 pid/窗口句柄，AutoLISP 的 32 位整数对 64 位句柄不可靠），属于 v7.2 的范围，这版不动。

## 回退

`交付\v7\CadImeLite.exe` 就是 v7 原件，双击即可回退；也提供了 `交付\回滚到v7.cmd` 一键回退。

## 升级注意

托盘程序正在运行时，`CadImeLite.exe` 这个文件是被锁住的，**不能直接覆盖**（exe 自装时的 `File.Copy` 会失败，然后因为单实例锁直接静默退出，表现是「双击没反应」）。

正确做法：先托盘右键 → 退出，再替换文件。`交付\更新到v7.1.cmd` 已把这三步做完（杀进程 → 拷贝 → 启动）。
